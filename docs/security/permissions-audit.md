**روش:** خواندن کد + اجرای واقعی سامانه و آزمون با سه کاربر ساختگی (ادمین، کاربر محدود به «حوزه ریاست»، کاربر بدون هیچ دامنه)

## ۱. مدل فعلی چگونه کار می‌کند

هر کاربر در جدول `auth_users` سه ستون دارد:

| ستون | محتوا | نقش |
|---|---|---|
| `role` | `admin` یا `user` | ادمین از همهٔ بررسی‌ها معاف است |
| `permissions` | JSON مثل `{"tab_report": true, "can_approve": false}` | مجوزهای «چه کاری» |
| `allowed_deputies` | JSON مثل `["معاونت سیما"]` | دامنهٔ «چه داده‌ای» |
| `allowed_centers` | JSON مثل `["شبکه تهران"]` | دامنهٔ «چه داده‌ای» |

سه تابع تصمیم می‌گیرند: `get_deputy_scope()` (None = همه، `[]` = هیچ)، `get_center_scope()`، و `perm_required()`.

**تصویر کلی پوشش (خروجی دقیق در `coverage-ledger.json`):**

```
کل مسیرها:            ۹۷
با اعمال دامنه (scope):   ۷   ← ۷٪
با مجوز ولی بدون دامنه:  ۷۱
بدون هیچ دروازهٔ مجوز:   ۲۰   (فقط «لاگین بودن» کافی است)
```

یعنی **۹۳٪ سامانه دامنهٔ دسترسی را اعمال نمی‌کند.**

## ۲. یافته‌ها

### 🔴 F-01 — مجوز «تأییدکننده» برای هر کاربر غیرادمین خطای ۵۰۰ می‌دهد

`web/app.py:1253-1256` از نامی استفاده می‌کند که وجود ندارد:

```python
if not perms_mod.has_perm(uid, 'can_approve'):   # NameError
    ...
dep_scope = perms_mod.get_deputy_scope(uid)
ctr_scope = perms_mod.get_center_scope(uid)
```

در ابتدای فایل ماژول به‌صورت `import web.permissions as perms` ایمپورت شده، پس `perms_mod` تعریف نشده است.

**اثبات اجرایی** (کاربر `test_approver` با مجوز `can_approve` و دامنهٔ «معاونت سیما»):

```
[۱] گزارش برای تاییدکننده: 1 ردیف
    تلاش تایید رکورد → 500 Internal Server Error
    NameError: name 'perms_mod' is not defined   (web/app.py:1253)
```

**اثر:** جریان «تأیید → نشستن در پرداختی ماه» برای هر کاربری که ادمین نیست **کاملاً از کار افتاده**. فقط ادمین می‌تواند تأیید کند. این دقیقاً همان چیزی است که شما حس کرده‌اید که کار نمی‌کند.

### 🔴 F-02 — دامنهٔ خالی یعنی «همه‌چیز» (fail-open)

`web/analytics.py` و `web/command_center.py`:

```python
if scope:                       # scope == [] → شرط False
    ... WHERE deputy IN (...)
# نتیجه: بدون هیچ فیلتری، همهٔ معاونت‌ها برمی‌گردند
```

**اثبات اجرایی** (کاربر `test_empty` با **صفر** معاونت مجاز و بدون `scope_all_deputies`):

```
[۲] /api/analytics/all             200  deputy_performance=1, monthly=1, kpi=6
[۲] /api/command-center/snapshot   200  feed=6, kpi=8, online_list=3
[۲] /api/summary-table             200  total_sum=39,416,000
[۲] /api/dashboard-charts          200  deputy_amounts=1, wage_distribution=6
```

کاربری که هیچ مجوز داده‌ای به او نداده‌اید، **کل دادهٔ سازمان** را می‌بیند.

### 🔴 F-03 — جدول خلاصه و نمودارها دامنه را نادیده می‌گیرند

`_build_summary_rows()` (app.py) هیچ پارامتری برای دامنه ندارد؛ `/api/summary-table` و `/api/summary-table/export` بدون فیلتر دامنه اجرا می‌شوند.

**اثبات اجرایی** (کاربر مجاز فقط به «حوزه ریاست»):

```
/api/summary-table?period=1404-مهر   200   rows=1  deputies=['معاونت سیما']   ← خارج از دامنه
/api/dashboard-charts?period=1404-مهر 200  deputy_amounts=[معاونت سیما]      ← همان نموداری که نباید ببیند
```

### 🔴 F-04 — جست‌وجوی پرسنل با کد ملی، محدودیت ندارد

`/api/person?national_code=...` (app.py) هیچ مجوز و هیچ دامنه‌ای ندارد. هر کاربرِ لاگین‌کرده می‌تواند کد ملی هر فرد را وارد کند و دستمزد، سابقهٔ ماهانه و پرداختی‌هایش را ببیند.

```
/api/person?national_code=0012345678   200   {person, records[دستمزد ۳۵٬۰۰۰٬۰۰۰], payments[...]}
```

این حساس‌ترین نشت داده در سامانه است: کد ملی + حقوق، حتی برای فردی که در هیچ معاونتی مجاز نیست.

---

### 🔴 F-05 — ایمپورت محدود، دادهٔ بقیهٔ معاونت‌ها را پاک می‌کند

`importer/excel_importer.py::_safe_delete_records_for_month()` ابتدا **همهٔ رکوردهای آن ماه** را حذف می‌کند:

```python
n_rec = conn.execute("DELETE FROM records WHERE period_month = ?", (period_month,)).rowcount
```

`/api/import` فقط `can_upload` را چک می‌کند و هیچ فیلتری روی محتوای فایل یا مالکیت رکوردها اعمال نمی‌کند.

**اثر:** کاربری که فقط به «شبکه تهران» مجاز است، با آپلود فایل ماه، **کل دادهٔ آن ماه در همهٔ معاونت‌ها را حذف** می‌کند و فقط ردیف‌های فایل خودش را جای آن می‌گذارد. این «دسترسی بیشتر از مجوز» در خشن‌ترین شکلش است.

همین مشکل در `/api/clear-month` هم هست: `can_clear_month` اجازهٔ پاک کردن **کل ماه** را می‌دهد، نه فقط دامنهٔ کاربر.

### 🟠 F-06 — مجوز تأیید، «و» منطقی است نه «یا»

`_approval_scope_check()`:

```python
ok_dep = deputy in dep_scope
ok_ctr = center in ctr_scope     # برای کاربری که مرکزی انتخاب نکرده: [] → False
if not ok_dep or not ok_ctr: return False, 403
```

شما در پنل کاربران «معاونت برون مرزی» را تیک می‌زنید و انتظار دارید تمام شبکه‌های زیر آن هم مجاز باشند. اما `get_center_scope()` مقدار `[]` برمی‌گرداند و شرط `ok_ctr` همیشه `False` است → **تأییدکننده‌ای که فقط معاونت گرفته، هیچ‌چیز نمی‌تواند تأیید کند.**

دامنه، اجتماع (`OR`) است نه اشتراک: اگر کسی «معاونت برون مرزی» + «شبکه فیلم» داشته باشد، `_build_report_scoped` همهٔ برون‌مرزی **به‌اضافهٔ** شبکه فیلم را می‌آورد — که تا حدی درست است، ولی هیچ راهی برای «فقط شبکه فیلم» وجود ندارد چون معاونت مجاز، تمام زیرمجموعه‌اش را باز می‌کند.

### 🟠 F-07 — پنل منابع انسانی هیچ دامنه‌ای ندارد

`web/personnel.py` صفر ارجاع به `session`، `perm` یا `scope` دارد. `/api/personnel`، `/api/personnel/enriched`، `/api/personnel/export` و ویرایش/انتقال/تغییر وضعیت، برای هر کاربر لاگین‌کرده باز است. و در UI، تب «منابع انسانی» با `can_upload` قفل شده (خط ۱۷۱۱ و ۱۷۲۵ در `index.html`) — یعنی برای *دیدن* پرسنل باید مجوز *آپلود* داشته باشی. این نگاشت غلط است.

### 🟠 F-08 — `/api/recalculate` و `/api/approval-log` بدون مجوز

```
POST /api/recalculate   → هر کاربر لاگین‌کرده می‌تواند کل موتور را روی همهٔ داده‌ها دوباره اجرا کند
GET  /api/approval-log  → مجوز can_view_audit تعریف شده ولی هیچ‌جا استفاده نشده
```

`/api/pricing-rules` (۸۲ قاعده از همهٔ معاونت‌ها)، `/api/all-centers` (۱۰۸ مرکز)، `/api/manual-ceilings`، `/api/specialists`، `/api/payment-grid` (همهٔ پرسنل و همهٔ مبالغ) و `/api/payments` هم بی‌مجوز و بی‌دامنه‌اند.

### 🟠 F-09 — رابط کاربری fail-open است

`index.html:1690`:

```js
function hasPerm(p) {
  if (window.__USER_ROLE === 'admin') return true;
  if (!window.__USER_PERMS) return true;   // ← اگر /api/me شکست بخورد، همه‌چیز نمایان است
  return !!window.__USER_PERMS[p];
}
```

اگر شبکه کند باشد یا سشن منقضی شود، همهٔ تب‌ها و باکس‌ها برای یک لحظه (یا برای همیشه، تا رفرش) نمایش داده می‌شوند. هر پنهان‌سازی UI باید «بسته به‌طور پیش‌فرض» باشد، نه باز.

همچنین ستون «تاییدیه مدیر» در جدول گزارش **همیشه** رندر می‌شود (خط ۱۰۹۸)؛ فقط دکمه‌های گروهی پنهان می‌شوند. کاربرِ بدون مجوز، چک‌باکس می‌بیند، تیک می‌زند و بعد ۴۰۳ می‌گیرد.

---

### 🟡 F-10 — نوع تأمین (تامین/پخش/تولید) در دامنه غایب است

مدل داده `centers_structure.supply_type` و `records.contract_subject` را دارد و شما در گزارش‌ها بر همین اساس جدا می‌کنید، اما `allowed_centers` فقط نام مرکز است. دامنهٔ «شبکه تهران — فقط پخش» قابل بیان نیست.

---

### 🟡 F-11 — دامنه فقط با «نام» تطبیق می‌شود

`allowed_centers` با `records.cost_center` مقایسه می‌شود، ولی نام مراکز از اکسل می‌آید و ممکن است فاصلهٔ اضافه، «ي» عربی یا نیم‌فاصله داشته باشد. `center_mapping.py` برای همین ساخته شده ولی در بررسی دامنه استفاده نمی‌شود. نتیجه: مرکز مجاز، به‌خاطر یک فاصله، «غیرمجاز» تلقی می‌شود (یا برعکس).

### 🟡 F-12 — هیچ لاگ دسترسی‌ای وجود ندارد

`log_action` فقط برای عملیات نوشتن استفاده می‌شود. هیچ‌جا ثبت نمی‌شود «چه کسی چه داده‌ای را دید». برای سامانهٔ حقوقی، ردپای دسترسی (access trail) لازم است.
